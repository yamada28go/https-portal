# P1で記録する既知挙動と後続課題

本書のC（characterization）は現在の出力を検知するための記録。望ましい安全性の承認や、実通信の安全性を示すものではない。製品コードは本対応では変更しない。

| ID | 現在の挙動 | P1の検知 | 後続判断・検証 |
|---|---|---|---|
| GAP01 | 非443ポート指定でもHTTPからのLocation相当の設定にポートを含めない | H04 | 4443等を含めるべきか仕様決定し、P2以降で修正・実HTTP応答確認 |
| GAP02 | HTTP→HTTPSは301、HTTPSの転送先指定は既定307 | H01、R04、R05で別々に検証 | 仕様変更時は両方を独立して判断 |
| GAP03 | renewal_spec.rbの期待ログと実装ログに既知差分がある | 判定UTにログ比較を混ぜない | P2で機能テストとログ仕様を整理 |
| GAP04 | 既存HTTPSヘルパーはVERIFY_NONEを使う | P1では実通信を行わず対象外 | P2/P3で信頼CA・チェーン・ホスト名を検証 |
| GAP05 | 既存機能テストは旧Compose・Docker Machine・実行順依存を含む | P1はファイルを限定しSKIP_BUILD=1 | P2で機能テストの導線・独立性を整備 |
| GAP06 | 設定文字列の合格だけではTLS交渉やHTTPステータス、upstream疎通は保証できない | 実ERB出力のみ検証 | P2/P3で301/307/308、401/200、IP制限、転送ヘッダー、CAを実通信確認 |

fixture内の認証文字列は架空の値のみ。A05は生成設定にそのユーザー名・パスワードを含めないことを検査する。
