# C-02：空値・異常入力の契約

## 対象と判定方針

ロードマップのC-02を `spec/models/domain_input_spec.rb` に29例として追加した。既存の正常入力26例は変更していない。全P1対象は54例から83例へ拡張した。

**今回の追加は現行挙動のcharacterizationであり、入力検証の安全性を承認するものではない。製品コードは変更していない。** 範囲外ポート等の拒否、明示的な例外への統一、全文一致等は別の製品修正・仕様レビューで扱う。

## 隔離

全例はp1タグの既存ヘルパーを使い、外部コマンド・本番ディレクトリ作成を行わない。今回DOMAINSもENVの初期化対象に追加した。例終了時とwith_contract_envの終了時には必ず復元する。

NoMethodErrorやTypeErrorを安全な入力拒否APIとは見なさない。入力拒否系は初期化途中の失敗と診断ログを検査し、ディレクトリ作成へ到達しないことを確認する。危険な入力の現行受理例はテスト名にcharacterizesを付け、望ましい仕様との差を明示する。

改行は既存D07/D08が許容するため一律に拒否しない。許可する構文上の改行と、未検査の別行を区別する仕様が必要。

## 検証状態

以前の54例・3 seed・単独実行・M01〜M05は利用者提供の実行結果で成功確認済み。今回の29例と83例への拡張は、このチャットからDocker Engineへ接続できないためRSpec未実行。既存54例の成功を新しい83例の成功と扱わない。追加後の結果を上記コマンドで再確認する。

C-07（ACME失敗系）とC-08（Nginx反映失敗系）は引き続き未実装。

実施済みの静的確認：PrismによるRuby構文解析、C-02-01〜29の重複・欠落なし、Compose構文と実行対象、検証スクリプトの83例/単独29例指定、製品コード・既存正常26例の変更なし、git diff --check。
